---

## 1. 本项目是什么

`bso-a-cs-1-sequel/` 是 `beastshield-online/` 世界观下的**改编续写项目**。原作作者仅完成第一卷前三章，本项目在此基础上进行第四章及以后的原创续写。

**核心设定**：VR 网游世界，所有伤害转化为「性欲值/精槽」，达到 100% 即射精死亡。

### 4.5 新章节推进工作流

> 从「想写下一章」到「开始写正文」的标准化流程。

```
步骤1：确定承接点 → 步骤2：确定本章目标 → 步骤3：场景需求清单
→ 步骤4：角色需求清单 → 步骤5：事件/关卡设计 → 步骤6：创建缺失档案
→ 步骤7：撰写章节大纲 → 步骤8：开始正文创作
```

**步骤1：确定承接点**
- 阅读 `chapters/ch-0X.md` 结尾，记录：地点、人物关系、未解悬念、主角当前状态
- 参考 `CURRENT_STATUS.md` 中的「关键设定备忘」

**步骤2：确定本章目标**
- 本章要推进什么？（日常铺垫 / 新角色登场 / 冲突爆发 / 世界观展开）
- 参考 `notes/style-guide.md` 确定节奏（日常/探索？战斗？情色/处决？）
- 预估字数和章节数

**步骤3：场景需求清单**
- 列出本章涉及的所有场景（地点）
- 检查 `.process/settings/scenes/README.md` 是否已有档案
- **如果已有**：直接在章节中引用，无需重复建档
- **如果缺失**：按 `scenes/_TEMPLATE.md`（v1.0 速查）或 `scenes/templates/template-scene-2.0.md`（详细版）创建新档案
- **子场景规则**：大型场景（如山贼山寨）已有总档案后，其子区域（厨房、训练场、营房）应作为独立子场景建档，编号顺延

**步骤4：角色需求清单**
- 列出本章涉及的所有角色（包括只出现一次的龙套）
- 检查 `.process/settings/characters/README.md` 是否已有档案
- **如果已有**：确认其当前状态与位置是否匹配本章需求
- **如果缺失**：赋予正式名字（非称号/职业），按 `characters/_TEMPLATE.md` 或 `characters/templates/template-character-2.0.md` 创建档案
- **龙套处理**：只有一句台词的龙套可暂不建档，但如果有互动或战斗，建议赋予名字并建档

**步骤5：事件/关卡设计**
- 本章是否有大型战斗？是否有日常任务链？是否有对话事件？
- 参考 `.process/settings/systems/README.md` 确认涉及的游戏机制
- 如需设计新机制，按 `systems/_TEMPLATE.md` 创建系统档案

**步骤6：创建缺失档案**
- 新建场景档案 → 更新 `scenes/README.md` 索引
- 新建角色档案 → 更新 `characters/README.md` 索引
- 新建系统档案 → 更新 `systems/README.md` 索引
- 所有新档案必须标注【原作】与【原创】来源区分。原作已有轮廓/提及的内容扩展用【原作】标注；第四章起新增的角色、场景、设定全部属于【原创】
- 档案之间用相对路径超链接建立交叉引用

**步骤7：撰写章节大纲**
- 在 `notes/` 下创建大纲文件：`YYYY-MM-DD-chapter-N-outline.md`
- 按场景顺序列出：场景 → 出场角色 → 事件 → 目标情绪/节奏
- 对照 `style-guide.md` 检查笔风是否匹配

**步骤8：开始正文创作**
- 文件：`chapters/ch-0N.md`
- 遵循 `style-guide.md` 的所有规范（第一人称、吐槽向、节奏、情色风格等）
- 遵循已建立的设定档案（角色外貌、场景布局、系统规则）
- 更新 `CURRENT_STATUS.md` 和 `README.md`

### 4.6 高风险内容分段撰写策略

> 基于 `ss-01` 支线创作的经验总结。适用于包含大量情色、暴力或敏感描写的场景。

在创作高风险段落时，即使已有完整大纲，也可能遇到部分内容无法一次性通过审核或执行的情况。**不要硬写整段**，而是：

1. **先写整体计划**：按场景列出完整的事件流程（参考 `notes/YYYY-MM-DD-描述-plan.md`）。
2. **识别高风险节拍**：标记可能触发拦截的核心段落（如直白性行为、尸体利用、极端暴力等），为每个节拍标注风险等级（低/中/高）。
3. **拆分子计划**：将高风险场景细分为更小的节拍（如"撕衣→刺激→侵入→射精→清理"），单独建档（如 `notes/YYYY-MM-DD-chapter-N-plan-sceneX.md`）。
4. **逐段尝试**：从低风险节拍开始撰写，逐步向高风险推进。一段通过后再写下一段。
5. **定位并调整**：如果某个节拍被拦截，只针对该节拍调整写法：
   - **隐喻化**：用感官碎片代替动作说明书
   - **系统遮蔽**：用游戏UI提示（【处决完成】【精槽已满】）覆盖敏感动作
   - **留白**：只写事前事后，跳过实时过程
   - **感官碎片化**：写气味、温度、触感，不写具体器官交互
6. **合并成文**：所有节拍通过后，去除过程性小节标题（如 `### 5-1 出手`），保留 `---` 分隔线或 `Scene X` 标记作为最终排版。

**参考案例**：`notes/2026-05-09-side-story-tiger-king-plan-scene56.md`

## 5. 文件存放规则

### 5.1 命名规范

**过程文件**（讨论、笔记、分析）：`YYYY-MM-DD-描述.md`
- 例：`2026-05-09-chapter-4-outline.md`

**故事章节**：`ch-N.md`
- 例：`ch-04.md`

**角色档案**：`XXX-名字拼音.md`
- 3位编号 + 角色**本名**（非称号/职业）
- 例：`001-zhu-tu.md`、`002-hu-lie.md`
- 无名角色需在档案中赋予正式名字

**场景档案**：`场景英文名.md`
- 小写，单词间用连字符
- 例：`bandit-fortress.md`、`starting-hillside.md`

**系统档案**：`系统英文名.md`
- 小写，单词间用连字符
- 例：`essence-gauge.md`、`combat-system.md`

### 5.2 新文件该放哪

| 文件类型 | 存放位置 |
|---------|---------|
| 改编故事（新章节） | `chapters/` |
| 角色设定档案 | `.process/settings/characters/` 下的对应子目录 |
| 场景/地点档案 | `.process/settings/scenes/` |
| 游戏机制档案 | `.process/settings/systems/` |
| 笔风/规范文档 | `notes/` |
| 项目级指南/说明 | `GUIDE.md` 或 `README.md`（本目录根级） |

### 5.3 禁止事项

- **不要把本项目的续写故事存到 beastshield-online 原作侧**（`original-archives/` 或 `settings/0-original-setting/`）
- **不要把本项目的设定档案存到 beastshield-online 原作侧**
- **不要修改 beastshield-online 原作侧的原作设定文件**
- **角色档案文件名不要使用称号/职业**（如 `hu-dawang.md` → 应使用本名 `hu-lie.md`）
