# 兽盾公司角色档案 · 建档规范

> 本文档记录角色档案系统的目录结构、分类规则、命名约定和建档流程。
> 在新建或更新档案时，先阅读此文档以保持一致。

---

## 一、目录与分类规则

### 1.1 目录结构
```
beastshield-company/
├── README.md                     # 总索引（兽种→已建档数）
├── {species}/                    # 兽种目录（dog, bear, bull, tiger, wolf, boar, lion, leopard, rhino）
│   ├── README.md                 # 兽种索引（等级分布 + 角色总览表）
│   ├── g/                        # G级杂兵（军绿色制服）
│   │   ├── README.md             # 等级索引
│   │   └── *.md                  # 角色档案
│   ├── e/                        # E级武斗兵（黑色紧身制服）
│   ├── o/                        # O级监工（蓝色制服）
│   ├── r/                        # R级枪械兵（白色紧身制服）
│   └── w/                        # W级摔跤兵（深蓝色连体摔跤服）
└── special/                      # 特殊角色（无制服等级的高层/头目等）
    ├── README.md
    └── *.md
```

### 1.2 分类铁律
- **有制服/等级的角色** → 按兽种+等级归入对应的 `species/rank/` 目录
- **无制服等级的角色**（董事长、大楼头目等）→ `special/`
- **反例**：虎队长穿E级黑制服，应归 `tiger/e/` 而非 `special/`

### 1.3 多章登场的角色
- 单个文件累积所有章的原文引用，按章节分段
- 能力、关系、结局等字段随时补充
- 在结局/章节引用处标注“待补充”直到角色故事完结

## 二、命名规范

### 2.1 角色档案文件
| 情况 | 格式 | 示例 |
|------|------|------|
| 有名字/编号的角色 | `name-or-id.md` | `tiger-captain-combat.md`, `ya-dong-chairman.md` |
| 无名角色 | `species-rank-vol-ch-NNN.md` | `bear-g-vol-1-ch-09-001.md` |
| 非兽盾阵营的无名角色 | `<篇>-ch-<N>-<NNN>.md`（放在对应阵营目录） | `others/dog-driver-babysitter-lei-ch-3.md` |
| **正文未指明兽种/制服的无名角色** | `unknown-<篇>-ch-<N>-NNN.md` | `others/unknown-corpse-mo-quan-ch-1-001.md` |

> **`unknown-` 命名规则（2026-09-17 首次启用）**：当一份档案的**正文既未给出兽种、也未给出制服等级**，
> 因而无法套用 `species-rank-…` 时，用 `unknown-<篇>-ch-<N>-NNN.md`，归入 `others/`。
> 档案正文必须把「兽种、毛色、制服、年龄、死因」等未指明项**逐条写「正文未指明」，不得推测或补全**。
> 首次实例：墨犬篇 ch-1 洞穴中与主角同处一室的兽人尸体（是主角身份的唯一线索，正文只写「一具兽人尸体」）。

> **“有名”的判定标准（2026-09-16 裁定）**：只认**故事正文**里出现的名字与编号。
> 仅出现在“故事评述与感慨”“他们最后的故事”等**非正文区块**的名字**不算**——
> **原故事没有名字就是没有名字**，一律用无名式命名。
>
> 本条用于消解 §2.1（有名字者用 `name-or-id`）与 §4 Step 1（建档时忽略评述区）之间的冲突。
> 反例：SS-007《毕业实习》评述区出现的 G-533~G-538 及“牛大壮”等姓名，正文从未出现，
> 故该篇 6 份档案全部沿用 `species-rank-ss-007-NNN.md` **是正确的**，无需改名。

文件名中：
- `vol` = 卷号（如 vol-1, vol-2）
- `ch` = 章节号（如 ch-09, ch-10）
- `NNN` = 该章内同兽种同等级角色的三位数序号（001, 002...）

### 2.2 章节引用格式
| 类型 | 格式 | 示例 |
|------|------|------|
| 主线 | `vol-N-ch-NN` | `vol-1-ch-09` |
| 支线/外传 | `s-N-chN-N` | `s-1-ch1-1` |
| 短篇 | `s-NN` | `s-01` |

### 2.3 相对链接
从 `beastshield-company/species/rank/xxx.md` 到故事正文：
```
../../../../chaptered-stories/main/bs-o-cm-1-main-story-1/ch-N-chapter-name.md
```

## 三、档案模板

每份档案严格按以下结构组织：

```markdown
# 角色名/特征描述

> 一句话定位（可选）

---

## 一、基本信息

| 项目 | 内容 |
|------|------|
| **种族** | 如：熊兽人（棕熊） |
| **等级/制服** | 如：G级 · 军绿色制服 |
| **编号** | 如有 |
| **身份** | 如：一楼大厅守卫 |
| **状态** | **已死亡/存活** |
| **首次登场** | [vol-1-ch-NN](链接) |
| **最后登场** | [同格式] |

---

![角色 · 场景](../../../../../images/commission/<作品编码>/<文件>.png)

## 二、外貌特征

- 特征列表（从原文提取）

---

## 三、性格特点

- （非必要，杂兵可不写）

## 四、登场原文

### [章节名](链接)

> 原文引用（保留粗体标记）

---

| 能力 | 描述 | 出处 |

---

*档案来源：*
*创建日期：*
```

### 3.1 章节编号规则（2026-09-17 裁定：**绝对编号**）

模板中的编号是**固定编号**，不随缺失的可选小节而前移：

| 编号 | 小节 | 可缺省 |
|------|------|--------|
| 一 | 基本信息 | 必有 |
| （不编号） | 配图 / Commissioned Art | 可选 |
| 二 | 外貌特征 | 可缺省 |
| 三 | 性格特点 | 可缺省 |
| **四** | **登场原文** | **必有** |
| 五 | 能力设定 | 可选 |
| 六 | 角色关系 | 可选 |
| 七 | 结局 | 必有 |

**关键点**：`## 四、登场原文` **恒为「四」**——即使该档案没有「二、外貌特征」与「三、性格特点」，也**不**把登场原文改成「二」或「三」。因此档案允许出现编号空档（如 `一、` → `四、` → `六、`）。

**为什么这样定**：约定文档与全部工具都以「四＝登场原文」为前提；编号前移会让同一小节在不同档案里编号不同，无法用脚本按编号定位，也无法做逐段机器校验。**代价是允许空档，收益是编号可预测。** 若某档案缺二/三，请直接缺省，不要补空标题占位，也不要顺延后续编号。

> 因历史原因，本库早期待建档案存在「二、登场原文」「三、登场原文」等写法（据审计约 201 份作「三」、115 份作「二」、35 份作「四」）。新写或重修档案一律按本节规则，逐批归一到「四」。

## 四、建档流程（逐章处理）

每章按以下顺序操作：

### Step 1：读一章
只读故事正文，忽略“故事评述与感慨”、“AI评述”等非正文部分。

### Step 2：提取角色
标记该章所有登场的兽盾兵：
- 物种、等级、是否有名字/编号
- 区分“有独立描写的角色”和“无区分的背景杂兵”

### Step 3：逐角色建档
- **有独立描写**（物种+死法+可引用原文）→ 独立文件
- **无任何区分度的背景杂兵**（如第9章体训房的昏睡杂兵战斗中的无名群演）→ 跳过或集体备注

### Step 4：更新三级索引
1. 更新该角色所属等级的 `README.md`
2. 更新该角色所属兽种的 `README.md`  
3. 更新总索引 `README.md`

### Step 5：提交
每章处理完后再提交，commit不暴露具体角色命运。

## 五、索引维护规则

### 三级索引结构
```
总索引（README.md）
 └─ 兽种索引（bear/README.md）
     └─ 等级索引（bear/g/README.md）
```

### 每次新增角色后同步更新
1. **等级 README**：添加一行到档案表格
2. **兽种 README**：更新已建档数 + 角色总览表新增一行
3. **总索引 README**：更新对应兽种的已建档数 + 更新故事覆盖范围 + 更新总计数

### 每次新增委托稿后同步更新（见第八节 8.4）
1. **角色档案**：`## 配图 / Commissioned Art` 区块（含画面出入说明）
2. **等级 README**：图墙 + 该行加 🖼 标记
3. **兽种 README**：等级索引表的“委托图”列 + 图墙 + 总览行加 🖼
4. **总索引 README**：索引总览的“委托图”列 + 按兽种图墙 + 逐张清单
5. **章节正文**：原位插图 + 章末 `## 插图索引`

## 六、检索与核对方法（防漏铁律）

> 建档、核对、讨论涉及“数出场角色/兵力”时，**先按下面的穷举法搜原文，再谈记忆**。
> 教训来源：`老雷突袭情报局 ch-2` 曾因依赖场景关键词（门神/站岗）和阅读记忆，漏掉数据中心门口的黑制服虎门神。

### 6.0 首选检索式：按兽种 + 按制服穷举

- **按兽种穷举**（覆盖面最全）：用兽种名直接搜正文，如
  `虎兽人|虎兽盾兵`、`牛兽人|牛兽盾兵`、`熊兽人|熊兽盾兵`、`野猪|猪兽人`……

  角色称呼里必然带兽种名，**哪怕他穿高级制服（E/R）也能被兽种词搜到**。
- **按制服/身份穷举**（兜底）：`黑制服|白制服|蓝制服|军绿`、`兽人|兵|站岗|巡逻|值守`。
- **不要依赖**场景孤立词（如门神、换岗、泡面、电梯）或阅读记忆——它们必然有盲区。

### 6.1 核对清单

1. 搜出兽种词的全部命中行 → 按场景/行号分组 → 判断每处指向同一角色还是不同角色
2. 区分“独立个体”与“同一角色的连续描写”（尤其注意原文笔误，如 ch-2 洗手间“虎兽人”实为熊）
3. 对照归档索引（等级 README / 兽种 README / 总 README）逐个点名，确认每个命中都有档案
4. 数兵力/角色数量一律**以索引清单为准**，不以记忆为准

### 6.2 检索工具建议

Grep/搜索时，命中行应带 `-n` 行号与上下文，便于按场景分组归属。

## 七、注意事项

### 6.1 杂兵建档原则
- 有名字/编号的角色固然要建档
- 无名的杂兵只要有**独立出场和死法**也应建档
- 区别开“有原文可引”和“纯背景板”

### 6.2 避免的错误
- ❌ 将E级制服角色放入 special/（虎队长教训）
- ❌ 同章同兽种同等级角色重名（如 boar-g-vol-1-ch-04-001 和 002 相撞）
- ❌ 忘记更新任何一级索引

### 6.3 制服速查
| 等级 | 制服色 | 袜子色 |
|------|--------|--------|
| G | 军绿色 | 白袜（袜口军绿条纹） |
| E | 黑色紧身 | 黑袜（袜口条纹因兵种而异） |
| O | 蓝色 | 白袜（袜口蓝色条纹） |
| R | 白色紧身 | 白袜（袜口蓝色圆环） |
| W | 深蓝色连体摔跤服 | 白袜（袜口蓝/紫条纹） |

## 八、配图规范 / Commissioned Art

> 当某个角色有对应的**委托稿插画**时，在档案中引用它。图库与命名规范见
> [`original-archives/images/commission/README.md`](../../../images/commission/README.md)。

### 8.1 位置与格式

**固定插在“一、基本信息”表之后、“二、…”之前**，用**不编号**的 `## 配图 / Commissioned Art` 标题：

```markdown
## 配图 / Commissioned Art

![<角色> · <场景>](../../../../../images/commission/<作品编码>/<文件>.png)

> 委托稿 · YYYY-MM-DD · <作品名>（[委托稿说明](../../../../../images/commission/<作品编码>/README.md)）
```

- **标题不编号**是刻意的：档案各节的“一、二、三…”编号保持不变，无需全档案重编号。
- 相对路径固定为 **`../../../../../images/commission/…`**（5 层：从 `兽种/等级/` 上溯到 `original-archives/`）。
- 同一角色有多张图时，并列多行。

### 8.2 必须标注“画面与原文的出入”

委托稿由画师再创作，**画面不等于原文**。若画面与原文有不一致（制服配色、动作姿势、姿势定格、原作未出现的元素如绷带/海报/编号），**必须**在配图下方补一行引用块说明：

```markdown
> ⚠️ 画面与原文的出入：……
```

这是档案可信度的一部分——不写会让后来者把画师发挥当成设定。

若画面还包含**其他已建档角色**（同框尸体等），用交叉引用标注：

```markdown
> 🔗 **交叉引用**：画面主体是……（档案见 [xxx](../../兽种/等级/xxx.md)）。
```

### 8.3 与图片目录的分工

- **图片目录**（`images/commission/<作品>/README.md`）负责：图本身的视觉细节、与原文的逐条出入、场景锚点。
- **角色档案**（本目录）负责：该角色自己的身份、外貌、登场原文，配图作为视觉补充。
- **章节正文**负责：原位插图 + 章末 `## 插图索引`。
- **三级索引**（总索引 / 兽种 / 等级 README）负责：**看图找角色**——用图墙与 🖼 标记让人一眼看出“哪些角色已有委托稿、长什么样、哪些还没有”。

四处互相链接，不要重复堆砌内容。

### 8.4 索引层的展示规范

委托稿必须在三级索引里都能直接看到图片，规范如下：

| 层 | 落点 | 写法 |
|----|------|------|
| 总索引 `README.md` | “索引总览”表 | 加 **委托图** 列：`🖼 <张数>`；无图写 `—`；同框写 `🖼 1🔗` |
| 总索引 `README.md` | `## 委托稿配图索引` | “一、按兽种看图”按兽种分节内嵌图片；“二、逐张清单”保留逐张表格 |
| 兽种 `{species}/README.md` | “等级索引”表 + `## 委托稿配图 / Commissioned Art` | 等级表加 **委托图** 列；图墙收该兽种全部委托稿 |
| 等级 `{species}/{rank}/README.md` | 顶部 `## 委托稿配图 / Commissioned Art`（插在简介引用块与档案表之间） | 图墙收该等级全部委托稿 |
| 各级总览表 | 档案名前的 **🖼 标记** | `| [🖼 tiger-g-mo-quan-ch-2-001](…) | 棕虎兽人 | … |` |

**图注统一格式**（三级索引共用，只有层级与路径深度不同）：条目标题必须是**标题行**（不是粗体），以确保在 Markdown 大纲（Outline）里能直接看到“哪个故事 · 哪个角色”：

| 层 | 兽种/等级 | 条目标题 | 路径深度 |
|----|----------|---------|---------|
| 总索引 | `###` | `####` | 3 层 |
| 兽种 README | （本文件即兽种层） | `###` | 4 层 |
| 等级 README | （本文件即等级层） | `###` | 5 层 |

```markdown
#### <作品名> <章节> · <角色简述>（<等级 / 画面备注>）

![<角色> · <场景>](<深度>/images/commission/<作品编码>/<文件>.png)

> 委托稿 · <YYYY-MM-DD> · <作品名>（[委托稿说明](<深度>/images/commission/<作品编码>/README.md)）· 🔗 同框：[<档案>](<路径>)
```

**路径深度**：总索引 **3 层**、兽种 README **4 层**、等级 README **5 层**（`../../../../..` 数到 `original-archives/`）。

约定：

- 图注里的“画面与原文出入”只写在**档案**与**图片目录**里；索引层最多写半句提示（如“画面为 O级蓝配色”），不三处重复堆砌。
- 无委托稿的兽种／等级在表格里写 `—`，不写“暂无委托稿”长句；`mixed/`、`special/` 因整目录无图，允许加一行说明。
- 🔗 = 同框入镜（非画面主体），必须在图注里点名画面主体是谁。
- 新增一张图 = 同步 **五处**：总索引（委托图列 + 图墙 + 逐张清单）、兽种 README、等级 README、角色档案 `## 配图`、章节正文原位 + 章末插图索引。
