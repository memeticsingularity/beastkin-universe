# 兽盾公司角色档案 · 建档规范

> 本文档记录角色档案系统的目录结构、分类规则、命名约定和建档流程。
> 在新建或更新档案时，先阅读此文档以保持一致。

---

## 一、目录与分类规则

### 1.1 目录结构
```
beastshield-company/
├── README.md                     # 总索引（兽种→已建档数）
├── {species}/                    # 兽种目录（dog, bear, bull, tiger, wolf, boar, lion, leopard, rhino）
│   ├── README.md                 # 兽种索引（等级分布 + 角色总览表）
│   ├── g/                        # G级杂兵（军绿色制服）
│   │   ├── README.md             # 等级索引
│   │   └── *.md                  # 角色档案
│   ├── e/                        # E级武斗兵（黑色紧身制服）
│   ├── o/                        # O级监工（蓝色制服）
│   ├── r/                        # R级枪械兵（白色紧身制服）
│   └── w/                        # W级摔跤兵（深蓝色连体摔跤服）
└── special/                      # 特殊角色（无制服等级的高层/头目等）
    ├── README.md
    └── *.md
```

### 1.2 分类铁律
- **有制服/等级的角色** → 按兽种+等级归入对应的 `species/rank/` 目录
- **无制服等级的角色**（董事长、大楼头目等）→ `special/`
- **反例**：虎队长穿E级黑制服，应归 `tiger/e/` 而非 `special/`

### 1.3 多章登场的角色
- 单个文件累积所有章的原文引用，按章节分段
- 能力、关系、结局等字段随时补充
- 在结局/章节引用处标注"待补充"直到角色故事完结

## 二、命名规范

### 2.1 角色档案文件
| 情况 | 格式 | 示例 |
|------|------|------|
| 有名字/编号的角色 | `name-or-id.md` | `tiger-captain-combat.md`, `ya-dong-chairman.md` |
| 无名角色 | `species-rank-vol-ch-NNN.md` | `bear-g-vol-1-ch-09-001.md` |

文件名中：
- `vol` = 卷号（如 vol-1, vol-2）
- `ch` = 章节号（如 ch-09, ch-10）
- `NNN` = 该章内同兽种同等级角色的三位数序号（001, 002...）

### 2.2 章节引用格式
| 类型 | 格式 | 示例 |
|------|------|------|
| 主线 | `vol-N-ch-NN` | `vol-1-ch-09` |
| 支线/外传 | `s-N-chN-N` | `s-1-ch1-1` |
| 短篇 | `s-NN` | `s-01` |

### 2.3 相对链接
从 `beastshield-company/species/rank/xxx.md` 到故事正文：
```
../../../../chaptered-stories/main/bs-o-cm-1-main-story-1/ch-N-chapter-name.md
```

## 四、建档流程（逐章处理）

每章按以下顺序操作：

### Step 1：读一章
只读故事正文，忽略"故事评述与感慨"、"AI评述"等非正文部分。

### Step 2：提取角色
标记该章所有登场的兽盾兵：
- 物种、等级、是否有名字/编号
- 区分"有独立描写的角色"和"无区分的背景杂兵"

### Step 3：逐角色建档
- **有独立描写**（物种+死法+可引用原文）→ 独立文件
- **无任何区分度的背景杂兵**（如第9章体训房的昏睡杂兵战斗中的无名群演）→ 跳过或集体备注

### Step 4：更新三级索引
1. 更新该角色所属等级的 `README.md`
2. 更新该角色所属兽种的 `README.md`  
3. 更新总索引 `README.md`

### Step 5：提交
每章处理完后再提交，commit不暴露具体角色命运。

## 五、索引维护规则

### 三级索引结构
```
总索引（README.md）
 └─ 兽种索引（bear/README.md）
     └─ 等级索引（bear/g/README.md）
```

### 每次新增角色后同步更新
1. **等级 README**：添加一行到档案表格
2. **兽种 README**：更新已建档数 + 角色总览表新增一行
3. **总索引 README**：更新对应兽种的已建档数 + 更新故事覆盖范围 + 更新总计数

## 六、检索与核对方法（防漏铁律）

> 建档、核对、讨论涉及"数出场角色/兵力"时，**先按下面的穷举法搜原文，再谈记忆**。
> 教训来源：`老雷突袭情报局 ch-2` 曾因依赖场景关键词（门神/站岗）和阅读记忆，漏掉数据中心门口的黑制服虎门神。

### 6.0 首选检索式：按兽种 + 按制服穷举

- **按兽种穷举**（覆盖面最全）：用兽种名直接搜正文，如
  `虎兽人|虎兽盾兵`、`牛兽人|牛兽盾兵`、`熊兽人|熊兽盾兵`、`野猪|猪兽人`……

  角色称呼里必然带兽种名，**哪怕他穿高级制服（E/R）也能被兽种词搜到**。
- **按制服/身份穷举**（兜底）：`黑制服|白制服|蓝制服|军绿`、`兽人|兵|站岗|巡逻|值守`。
- **不要依赖**场景孤立词（如门神、换岗、泡面、电梯）或阅读记忆——它们必然有盲区。

### 6.1 核对清单

1. 搜出兽种词的全部命中行 → 按场景/行号分组 → 判断每处指向同一角色还是不同角色
2. 区分"独立个体"与"同一角色的连续描写"（尤其注意原文笔误，如 ch-2 洗手间"虎兽人"实为熊）
3. 对照归档索引（等级 README / 兽种 README / 总 README）逐个点名，确认每个命中都有档案
4. 数兵力/角色数量一律**以索引清单为准**，不以记忆为准

### 6.2 检索工具建议

Grep/搜索时，命中行应带 `-n` 行号与上下文，便于按场景分组归属。

## 七、注意事项

### 6.1 杂兵建档原则
- 有名字/编号的角色固然要建档
- 无名的杂兵只要有**独立出场和死法**也应建档
- 区别开"有原文可引"和"纯背景板"

### 6.2 避免的错误
- ❌ 将E级制服角色放入 special/（虎队长教训）
- ❌ 同章同兽种同等级角色重名（如 boar-g-vol-1-ch-04-001 和 002 相撞）
- ❌ 忘记更新任何一级索引

### 6.3 制服速查
| 等级 | 制服色 | 袜子色 |
|------|--------|--------|
| G | 军绿色 | 白袜（袜口军绿条纹） |
| E | 黑色紧身 | 黑袜（袜口条纹因兵种而异） |
| O | 蓝色 | 白袜（袜口蓝色条纹） |
| R | 白色紧身 | 白袜（袜口蓝色圆环） |
| W | 深蓝色连体摔跤服 | 白袜（袜口蓝/紫条纹） |

## 八、配图规范 / Commissioned Art

> 当某个角色有对应的**委托稿插画**时，在档案中引用它。图库与命名规范见
> [`original-archives/images/commission/README.md`](../../../images/commission/README.md)。

### 8.1 位置与格式

**固定插在「一、基本信息」表之后、「二、…」之前**，用**不编号**的 `## 配图 / Commissioned Art` 标题：

```markdown
## 配图 / Commissioned Art

![<角色> · <场景>](../../../../../images/commission/<作品编码>/<文件>.png)

> 委托稿 · YYYY-MM-DD · <作品名>（[委托稿说明](../../../../../images/commission/<作品编码>/README.md)）
```

- **标题不编号**是刻意的：档案各节的「一、二、三…」编号保持不变，无需全档案重编号。
- 相对路径固定为 **`../../../../../images/commission/…`**（5 层：从 `兽种/等级/` 上溯到 `original-archives/`）。
- 同一角色有多张图时，并列多行。

### 8.2 必须标注「画面与原文的出入」

委托稿由画师再创作，**画面不等于原文**。若画面与原文有不一致（制服配色、动作姿势、姿势定格、原作未出现的元素如绷带/海报/编号），**必须**在配图下方补一行引用块说明：

```markdown
> ⚠️ 画面与原文的出入：……
```

这是档案可信度的一部分——不写会让后来者把画师发挥当成设定。

若画面还包含**其他已建档角色**（同框尸体等），用交叉引用标注：

```markdown
> 🔗 **交叉引用**：画面主体是……（档案见 [xxx](../../兽种/等级/xxx.md)）。
```

### 8.3 与图片目录的分工

- **图片目录**（`images/commission/<作品>/README.md`）负责：图本身的视觉细节、与原文的逐条出入、场景锚点。
- **角色档案**（本目录）负责：该角色自己的身份、外貌、登场原文，配图作为视觉补充。
- **章节正文**负责：原位插图 + 章末 `## 插图索引`。

三处互相链接，不要重复堆砌内容。
