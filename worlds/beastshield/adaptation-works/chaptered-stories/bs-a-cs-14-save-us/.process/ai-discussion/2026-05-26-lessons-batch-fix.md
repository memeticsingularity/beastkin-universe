# 批量修正经验记录

> 日期：2026-05-26
> 背景：一次性修正了全项目约40+角色档案的纪年体系、生日格式、经济数据、家庭关系、制服规格等问题。

---

## 教训一：角色档案不能留"不明"

最容易被偷懒写成"不明"的字段：出生日期、家庭关系（父亲/生父）、经济数据。

**后果**：每个"不明"都需要后续返工，而且返工时已经没有上下文了，容易编出前后矛盾的内容。

**规则**：设定档里的每一个字段都必须有具体内容。即使是配角也要有出生年、父母、工资。如果有意设置为神秘（比如雪豹俘虏的身世），也要给一个具体的出生日期，神秘感靠剧情表现，不是靠留空。

---

## 教训二：纪年体系必须一开始就统一

**问题**：项目里有三个互不兼容的纪年体系同时存在：
- 正确体系：白历270-320（故事年=317）
- 错误体系1（L-08）：白历36-65（被AI凭空生成的）
- 错误体系2（L-10/L-11）：白历110-144（同上）
- 错误体系3（L-04）：白历1032-1059（同上）

这导致了一次大规模的全局sed/perl偏移修正，不仅改动了日期字段，还改动了角色档案正文里的时间线叙述（比如"### 白历X年（X岁）"）。幸运的是偏移量在同一批文件内是一致的，否则根本没法批量修正。

**规则**：新人/新Agent创建角色档案时，必须先查 timeline.md 确认故事基准年（白历317年），出生年 = 317 - 年龄。不允许AI自己"推测"纪年。

## 教训三：世界设定是唯一权威来源，不能靠AI记忆

**问题**：体重基准（300+斤=150kg+）、制服规格（G级=军绿色短袖+短裤+白袜+运动鞋）、工资表（G=100/O=200/E=500/W=1000）全部记录在 world-setting.md 中，但AI在创建角色档案时经常无视这些设定，自己"推断"出错误的数值。

**后果**：体重偏低（犬兽人70kg）、制服穿错（长裤→短裤、军靴→运动鞋）、工资来源混乱（用了非原作数据）。

**规则**：AI在创建角色档案前，必须确认以下四个核心基准数据：
1. 体重区间（熊/牛 195-215kg，虎/猪 170-185kg，犬 150-160kg）
2. 制服规格（G级/ O级/ E级/ W级四套标准制式）
3. 工资表（G=100/O=200/E=500/W=1000 撸币/月）
4. 当前故事年（白历317年）

## 教训四：代词和称谓是全作级规则，不能逐文件依赖AI判断

**问题**：
- 全作只有"他"，没有"她"（世界观设定：只有雌雄同体的男兽人）
- 父母称谓：父亲/生父（没有"母亲"，没有"妈妈"）
- 配偶称谓：未婚夫/丈夫（没有"未婚妻"、"妻子"、"嫂子"等女性化称谓）

这些规则在设定文档中有记录，但分散在多处，AI在创建单个档案时不会主动翻查，导致29个文件出现了"母亲"、11个文件出现了"她"、多个文件出现了"未婚妻"。

**规则**：需要有一个"角色档案创建清单"——在创建任何新角色档案时，必须在最后自查：
- [ ] 所有代词的性别是否正确（只有他）
- [ ] 所有家庭称谓是否正确（父亲/生父/未婚夫）
- [ ] 所有字段是否都填了具体内容（无"不明"）

## 教训五：批量操作要确认文件已被读取

**问题**：Edit 工具要求目标文件在当前对话中被 Read 过，否则会失败。批量修改大量文件时，逐个读取再编辑效率极低。

**解决方案**：对于大规模（10+文件）的重复性修改，直接用 perl/sed 正则通过 Bash 工具执行，效率远高于逐文件 Edit。但使用 sed/perl 时要极其小心正则表达式，避免误伤。

**本次使用的批量偏移示例**（可复用于未来）：
```bash
# 纪年偏移 +252（L-08 Group A）
perl -i -pe 's/白历(\d+)年/"白历" . ($1+252) . "年"/ge' file1.md file2.md ...

# 纪年偏移 -742（L-04）
perl -i -pe 's/白历10(\d{2})年/"白历" . (1000+$1-742) . "年"/ge' file1.md file2.md ...

# 生日批量替换（sed）
sed -i 's/| \*\*出生日期\*\* | 旧值 |/| **出生日期** | 新值 |/' file.md
```

## 教训六：索引文件的路径引用会持续腐烂

**问题**：角色文件被移动或重命名后，levels/ 下的 index.md 中的路径引用不会自动更新。本次修复了 L-05/L-07/L-09/L-11 四处路径断裂。

**规则**：每次角色文件变更（移动/重命名/新增）后，必须同步检查所有引用该文件的 index.md。或者更彻底的做法：在 levels/index.md 中使用相对路径约定，并在项目规范中记录文件组织方式。

## 教训七：不要一次性做太多事

本次会话中完成了以下操作，每项都有互相依赖关系：
1. 修正全项目代词（她→他）+ 亲属称谓
2. 修正经济数据和家庭关系
3. 修正制服规格
4. 创建5个角色档案
5. 修复index路径
6. 统一纪年体系（4组偏移）
7. 给41个角色分配生日
8. 创建时间线基准文件

每一步完成后都没有停下来验证再推进，如果第6步的纪年偏移算错了（偏移量不一致），会直接破坏第7步的生日数据。

**规则**：批量修改应该分批进行，每完成一批就 grep 验证一次。本次侥幸没出错，但不能依赖运气。

## 教训八：世界观核心机制必须在角色档案中体现

**问题**：所有角色档案最初写作时忽略了世界核心机制——**伤害→性欲值（精槽）转化，射精=死亡**。角色的战斗/处决事件写成了纯暴力描写（割喉、打断骨头），完全不符合世界设定。

**解决方案**：为每个角色添加 `## 性机制` 区块（含特有敏感部位、精槽特性、制服性特征、性互动方式、性偏好维度五项），并将时间线中的事件改写为精槽管理导向的性化描写。

**涉及范围**：~57个角色档案 + README + template + species-traits 等系统文件

## 教训九：「Side」性偏好概念的引入

**问题**：角色性互动方式单一化——默认都是插入式性行为，忽略了非插入式（Side）的可能性。

**Side 定义**：Side 指非插入式性偏好——更倾向亲吻、抚摸、口交、互相自慰、腿交等方式。这不是无性恋，只是性亲密不必以插入为核心。

**对角色设计的影响**：
1. 处决方式可多样化——口交致死、互相自慰比赛、腿交控精等
2. 亲密关系多样化——炮友不一定是插入式，互相抚摸、拥抱同样常见
3. 需要在性机制表中增加 `性偏好维度` 行

**规范更新**：template 和 README 已加入 Side 概念说明和 checklist 项。
