# 改编工作流 v1.0 — 从原文到多轮专项优化

> 把一次改编扩写拆成若干个独立阶段，每阶段只盯一个维度，产出清晰、前后不互相污染。
> 适用于：基于 bs-o-s / bo-c 等原作的短篇扩写或章节重写，放入 adaptation-works 目录后使用。
>
> 来源：bs-a-s-4-babysitter-lei 完整改编过程复盘

---

## 核心理念

**一次只修一个维度。** 不要在扩写的同时追求射精描写到位、感官丰富、语感自然——这些目标会互相拉扯。先把骨架搭好，然后一轮一轮地专项优化。

改编和原创不一样：改编的"好"不等于"写得漂亮"，等于"在保留原作风味的前提下做有针对性的强化"。所以每一轮专项都要回答同一个问题：**这一步改完，原作读者读了觉得被强化了还是觉得被稀释了？**

---

## 六阶段总览

```
Phase 1  基础搭建        建目录 → metadata → 确认scope
    ↓
Phase 2  扩写            选段 → 按原作笔风展开
    ↓
Phase 3  过程文件        status → plan → 记录决策
    ↓
Phase 4  专项循环 (最多可4轮，顺序执行)
  4a  射精描写专家       一定五要 + 增量结构 + 量级梯度
  4b  感官序列专家        五感空间锚定 + 感官不重叠
  4c  世界观规则专家      乳汁/制服/物种/术语一致性
  4d  ← 如果4a-4c产生了新内容，回到Phase 2检查衔接
    ↓
Phase 5  收口            审阅眼评分 → 语感修 → final
    ↓
Phase 6  提交            原文侧检查 → 版本号commit
```

---

## Phase 1: 基础搭建

### 目标
在 adaptation-works 下建立正确的目录结构，确保改编不影响原作。

### 操作

1. **确认工作侧**
   - 原文在 original-archives → **不改**
   - 改编写在 adaptation-works → **新建**

2. **决定编号**
   - 短篇扩写：`bs-a-s-[序号]-简短描述`
   - 章节改编：`bs-a-cs-[序号]-简短描述`
   - 序号取 adaptation-works 下同类型最大编号 +1

3. **建目录结构**
   ```
   bs-a-s-N-name/
   ├── bs-a-s-N-name.md        # 改编正文
   ├── metadata.yaml            # 改编元数据
   └── .process/
       ├── CURRENT_STATUS.md    # 进度追踪
       └── plans/
           └── expansion-plan.md  # 扩写计划
   ```

4. **metadata.yaml 必填字段**
   ```yaml
   title: 中文标题（扩写版）
   title_en: English Title
   story_info:
     based_on: bs-o-s-N-xxx    # 原作编号——这是一切的源头
   expansion_notes:
     original_story: "bs-o-s-N"
     original_author: "xxx"
     expansions:
       - scene: "场景描述"
         original_length: "原文长度"
         expanded_length: "扩写后长度"
         style: "笔风说明"
   ```

### 质量门
- [ ] 确认 original-archives 下**无**新建文件
- [ ] 确认 adaptation-works 下的目录编号不冲突
- [ ] metadata 中 based_on 指向正确的原作编号

## Phase 2: 扩写

### 目标
在保留原作笔风的前提下，选择性地展开缩略段落。

### 选段判断标准

原文中哪些地方适合扩写：

| 特征 | 判断 | 优先级 |
|------|------|:------:|
| 时间跳切（"两分钟后"） | 过程被跳过，有内容可写 | ★★★ |
| 摘要式战斗（"一拳一个打射了"） | 高光时刻被概括 | ★★★ |
| 一笔带过的死亡（"几天后垃圾桶里的尸体"） | 倒叙式省略 | ★★ |
| 逻辑缺环（角色A→突然→角色B死了） | 中间缺失 | ★★ |
| 对话代替动作（"啊啊"两声→战斗结束） | 听觉代替视觉 | ★ |

### 扩写三原则

1. **不加新设定**——扩写只展开原文已有的内容，不创造新角色/新能力/新世界观规则
2. **不改变结局**——不管怎么扩，角色的下场只能是原文既定的下场
3. **笔风跟随原文**——这段如果lanse来写会怎么写？参考 `author/001-lanse/style-analysis/` 中对应作品的风格分析

### 质量门
- [ ] 扩写后原文所有关键剧情点不受影响
- [ ] 去掉扩写标记后，文本和原文上下文读起来仍是一体的
- [ ] 没有新增角色或设定

---

## Phase 3: 过程文件

### 目标
记录创作决策，让后续每个阶段知道前面做了什么、为什么。

### 输出

**CURRENT_STATUS.md** — 项目级状态，包含：
- 项目概览（原作/改编类型/版本记录）
- 已完成内容（每轮扩充的scenario覆盖和叙事功能）
- 扩写决策记录（笔风对照表、战斗方式区分表）
- 待完成/可迭代方向

**plans/[场景]-plan.md** — 单次扩写的设计文档，包含：
- 选段理由（为什么扩这里）
- 边界定义（哪里开始、哪里结束）
- 设计要点（要写入什么、不写入什么及理由）
- 笔风对照清单（逐项打勾）
- 衔接方案（原文出入点、标记方式）

### 质量门
- [ ] CURRENT_STATUS 版本号和正文一致
- [ ] plan 中包含了"不被写入的方向"（排除的理由和选择同样重要）

## Phase 4: 专项循环

这是改编工作流的**核心差异化环节**——每一轮只检查一个维度，不分心。

### 顺序是固定的

```
4a 射精描写 → 4b 感官序列 → 4c 世界观规则
```

不能颠倒。因为4a可能修正射精用词，4b改感官描写时会写到射精场景所以必须先让4a改完；4c检查世界观规则时会触及前两轮的内容但不能反过来修。

### 4a: 射精描写专家

**参考文件：**`author/001-lanse/write-skills/lanse-ejaculation-expert.md`

**检查清单：**
- [ ] 铁律一：每个角色射股数符合其价值（10-15 标准 / 7-8 下限 / 15-20 爆发）
- [ ] 铁律二：增量结构而非递减——"一股接一股，喷了十几股"，不是"第五股——稀了"
- [ ] 铁律三：第一/二股动词用"喷"而非"流/淌/滴/挤"
- [ ] 死亡格式塔完整（濒临→绷直→龟头→第一股→持续→身体反应→残精→死亡确认）
- [ ] 全篇多场死亡有量级梯度（G级 < 高级兵 < BOSS）
- [ ] 老手杀手处决有"挤残精"步骤
- [ ] 精液去向清晰（射在墙上/裤裆里/方向盘上）
- [ ] 情感调色盘有区分（高潮/失控/羞耻/悲壮至少2种）

### 4b: 感官序列专家

**参考文件：**`author/001-lanse/style-analysis/lanse-positive-creation-supplement.md` 机制一 + 机制四

**检查清单：**
- [ ] 每个场景有至少 1 个独特的嗅觉锚定（不是"各种气味混合在一起"）
- [ ] 触觉/材质：角色接触的表面有质感描写（瓷砖冰凉/地毯短绒/皮革黏涩）
- [ ] 环境听觉：至少有 1 处环境音（脚步声/管道声/电器声/回声）
- [ ] 温感梯度：场景之间有明确的温差变化（夜风→走廊→浴室→车内）
- [ ] 空间锚定：每个场景有 2-3 个独特空间特征（月光角度/水垢印记/家具布局）
- [ ] 感官不重叠：每个感官维度只在最佳时机出现一次
- [ ] 描写附着在行动上：没有独立成段的环境描写

### 4c: 世界观规则专家

**参考文件：**`AGENTS.md`「写作规则」（兽盾角色必填内容 / 世界观不可违反规则）

**检查清单：**
- [ ] 死亡必有射精（射精=死亡绑定，没有例外）
- [ ] 乳汁分泌：乳头受性刺激分泌乳汁已写入（至少出现1次）
- [ ] 制服色与等级匹配（G军绿白袜 / O蓝白袜 / E黑黑袜）
- [ ] 物种白名单：兽盾兵仅限熊/虎/牛/猪/犬科+狼（无豹/鬣狗/鹿/兔/羊）
- [ ] 体型铁律：兽盾兵无"精瘦"描写（精壮/粗壮/壮硕）
- [ ] 无女性代词——全文仅用"他"
- [ ] 长筒袜每章至少出现1次，有包裹感描写

### 质量门（每轮）
- [ ] 专项文件已在 `author/001-lanse/` 中确认存在
- [ ] 本轮修改没有自创新规则（所有改动都有参考源）
- [ ] 修改后通读前后文，确认衔接不断

## Phase 5: 收口

### 目标
模拟原作者审阅，修语感，输出终稿。

### 5a: lanse 审阅眼

**参考文件：**`worlds/beastshield/skills/lanse-review/lanse-review-guide.md`

逐维评分：
- D1 风味还原度：叙述温度一致？描写附着在行动上？
- D2 核心标记：长筒袜/登场公式/道体系/省略号？
- D3 肉体吸引力：够不够壮？精液有分量感吗？
- D4 死亡美学：差异化？仪式感完整？
- D5 语感自然度：有没有AI腔？段落节奏对吗？

目标评级：**🔥 这很可以** 或 **👍 还不错**。如果落到了🤔，修完再报。

### 5b: 语感自然度专项

**常见AI腔（必须检查）：**
- [ ] "不是……而是……"对比句式 → 直接写结论
- [ ] "XX混合在一起"（气味类）→ "闷成了一片""分不清彼此"
- [ ] "他能感到/感觉到/意识到"过量 → 直接写客观状态
- [ ] "各种XX" → 具体写一种，不写"各种"
- [ ] 段落均匀偏长 → 拆成1-3句/段
- [ ] 对话标签 "说" 代替 "道" → 改为"说道/问道/吼道/笑道"

### 质量门
- [ ] 没有"不是……而是……"句式（原文自带的除外）
- [ ] 没有"XX混合在一起"（气味类）
- [ ] 没有过量的"他能感到/感觉到"
- [ ] 没有10句以上的超长段

## Phase 6: 提交

### 6a: 确认原文侧未被误改

```bash
git status worlds/beastshield/original-archives/
# 应为空或只有与本次改编无关的改动
```

如果有意外改动：`git checkout -- <path>` 恢复。

### 6b: 版本号规则

```
v1.0  — 扩写完成（Phase 1-3）
v1.1  — 新扩写段落追加
v1.2  — 射精描写强化
v1.3  — 感官深度增强
v1.4  — 语感修复/世界观补全
v2.0  — 全文重写或大量修订
```

数字不代表质量，只代表轮次。关键是每次commit的message写明本轮改了什么。

### 6c: commit message 格式

```
<type>: bs-a-s-N-name vX.Y 改动描述

[维度1] 具体条目
[维度2] 具体条目

每条改动可追溯到一个专项专家或决策记录
```

## 常见翻车点

| 翻车 | 出现在哪一阶段 | 怎么防 |
|------|--------------|--------|
| 直接在 original-archives 里改 | Phase 1 | 建好目录后先确认git status |
| 扩写段和原文段笔风不一致 | Phase 2 | 扩写前读2-3遍原文，感受语调 |
| 过程文件拖到收尾才补 | Phase 3 | 扩写完立刻建.process |
| 虎兽人没射精（世界观违规） | Phase 4c | 4c的死亡必射检查不跳过 |
| 所有角色死法雷同 | Phase 4a | 写checklist时逐角色对比差异维度 |
| "不是……而是……"全文遍布 | Phase 5b | 做语感修之前先grep一遍 |
| 提交后才意识到原文被改 | Phase 6 | 每阶段结束跑一次 `git status original-archives/` |

## 这个工作流怎么来的

bs-a-s-4-babysitter-lei 的改编经历了以下实际路径：

```
Step 1  直接改了原文 → 用户纠正 → 移入 adaptation-works  ← 基础搭建教训
Step 2  扩写双牛兽人对决（v1.0）
Step 3  扩写虎兽人灭口（v1.1）
Step 4  射精描写强化（v1.2） ← 第一次专项
Step 5  全篇感官增强（v1.3） ← 第二次专项
Step 6  乳头泌乳+语感修+肉壮（v1.4） ← 第三次专项+审阅
```

实际的改编次数比必要多了一倍——因为前两次不知道有专项专家存在，后面才发现每轮只盯一个维度比一次修完要干净。

本工作流把这6轮迭代**压缩成3轮专项 + 1轮收口**，因为顺序固定、目标不重叠。
