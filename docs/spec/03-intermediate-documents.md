# Beastkin Universe 中间文档规范 v3.0

> "中间文档"指创作过程中产生的非正文文件：README、设定、过程记录、变更日志、AI 讨论等。本文档定义它们的命名格式和内容要求。

---

## 1. 根级 README.md

项目根目录的 `README.md` 是全宇宙导航入口，必须包含：

```markdown
# Beastkin Universe

## 一、内容分级
## 二、世界观概览（全部 10 个）
## 三、发现故事（按 tag / 兽人 / 要素过滤入口）
## 四、快速访问
## 五、项目结构
## 六、许可协议
```

---

## 4. 故事类型 README.md

`chaptered-stories/` 和 `short-stories/` 目录的 `README.md`：

```markdown
# 长篇分章故事 / Chaptered Stories

> 返回上级：[档案根](../../README.md)

## 一、形式说明
## 二、阅读地图（策展式导语，告诉读者从哪里开始看）
## 三、作品列表（每个作品必须附一句话简介，禁止只有编码和标签）
## 四、发现入口（至少包含"按心情/场景推荐"和"按标签筛选"）
## 五、创作规范速查
```

**内容质量要求**：
- **一句话简介**：每个作品必须用一句话勾起阅读欲望，不要平铺直叙描述剧情
- **阅读地图**：必须包含策展式导语，引导不同需求的读者找到入口
- **按心情分组**：作品数量 ≥4 时，必须按主题/风格/情绪分组，禁止只有一个大表格
- **发现入口**：必须包含"按心情选故事"表格，从读者视角出发（"你想感受…→推荐作品"）

## 7. 作品目录 README.md

### 7.1 强制 Section

```markdown
# {中文标题} / {English Title}

> 状态：{updating|completed|abandoned} · 编码：`{code}` · 作者：{author} · 最后更新：{YYYY-MM-DD}

## 简介
（100-300 字故事梗概）

## 章节列表 / Chapters
- [Ch.1 {标题}](ch-001-xxx.md)
- [Ch.2 {标题}](ch-002-xxx.md)

## 创作留痕
- [查看变更日志](.process/CHANGELOG.md)
- [查看 AI 讨论索引](.process/ai-discussion/INDEX.md)
```

### 7.2 可选 Section

| Section | 何时需要 |
|---------|---------|
| `## 内容分级与警告` | **强制**。所有作品必须使用四维分级矩阵（🔞💀🧠⚡），详见 `13-rating-criteria.md` |
| `## 内容标签与核心元素` | **强制**。必须使用九类标签体系（🐾🔞⚔️🏛️🎭🎨🗺️🧩🎯），详见 `13-rating-criteria.md` |
| `## 专属设定` | 作品有独特设定时，链接到 `settings/story-setting.md` |
| `## 关联作品` | 有前传/续集/改编来源时 |
| `## 评述` | 作品完成后的人物命运评述 |

## 9. .process/ — 创作过程目录

每个作品目录下必须包含 `.process/`，存放所有非最终正文的文件。

```
.process/
├── CHANGELOG.md          # 作品级变更日志（为什么改）
├── ai-discussion/
│   ├── INDEX.md          # AI 讨论总览索引
│   └── {日期}-{主题}.md   # 单次讨论记录
├── plan/
│   └── {版本}-{类型}.md
├── history/
│   └── {日期}-{事件}.md
├── design/
│   └── {主题}-{类型}.md
└── archive/
    ├── {文件名}-v{旧版本}.md        # 旧版本正文
    └── {文件名}-v{旧版本}.obsolete.md  # 弃用原因说明（必须伴随）
```

### 9.1 CHANGELOG.md — 作品级变更日志

记录每次对作品目录内文件的重大变更。Git 记录 `what`，CHANGELOG 记录 `why`。

**格式**：

```markdown
# 变更日志

## {YYYY-MM-DD} — {一句话摘要}
- **变更类型**: {create|rewrite|adjust|deprecate|promote}
- **影响范围**: {文件名列表}
- **原因**: {为什么做这次变更}
- **具体内容**: {改了什么}
- **参考讨论**: {关联的 ai-discussion 文件，可选}
```

**变更类型说明**：

| 类型 | 含义 |
|------|------|
| `create` | 新建章节/作品 |
| `rewrite` | 重写某章节 |
| `adjust` | 调整细节（增删段落、修改措辞） |
| `deprecate` | 弃用某版本/章节（需同步写入 archive/ 的 .obsolete.md） |
| `promote` | 作品从改编晋升为原创 |

### 9.2 ai-discussion/ — AI 讨论记录

**单条记录命名**：`{YYYY-MM-DD}-{主题}.md`

**内容格式**：
```markdown
# {主题}

**日期**: {YYYY-MM-DD}
**参与者**: {AI 模型/工具名}
**结论状态**: {已落实|部分落实|待落实|已否决|仅参考}

## 讨论背景
{为什么发起这次讨论}

## 核心问题
{具体的问题或分歧点}

## AI 建议摘要
{分点列出 AI 的核心建议}

## 作者决策
{采纳了哪些、拒绝了哪些、原因是什么}

## 落实追踪
- [ ] {待办项1}
- [x] {已完成项}
```

**INDEX.md — 讨论索引**：

```markdown
# AI 讨论索引

| 日期 | 主题 | 核心结论 | 结论状态 | 关联文件 |
|------|------|---------|---------|---------|
```

### 9.3 archive/ — 版本归档与弃用说明

旧版本文件迁入 `archive/` 时，**必须**创建同名的 `.obsolete.md` 文件。

**弃用说明格式**：

```markdown
# {文件名} 弃用说明

**弃用日期**: {YYYY-MM-DD}
**替代版本**: {新文件名}

## 为什么弃用
{总体原因：节奏问题？设定冲突？不符合期望？}

## 具体不足
- {不足1}
- {不足2}

## 新版本改进
- {改进1}
- {改进2}

## 是否可复用
{哪些片段、设定或描写可在未来作品中复用}
```

## 10. 版本迭代文件命名规范

所有版本化文件统一采用：

```
{basename}-v{主版本}.{次版本}.md
```

**规则**：
- 使用连字符 `-`，禁止使用下划线 `_`
- 版本号格式为 `M.m`（主.次），禁止 `v1`（缺少次版本）
- 禁止 `plan_v2.md`、`README_v1.md` 等旧格式

**示例**：

| 旧格式 | 新格式 |
|--------|--------|
| `README_v1.md` | `README-v1.0.md` |
| `plan_v2.md` | `plan-v2.0.md` |
| `plan_v1_1.md` | `plan-v1.1.md` |
| `story_v3.md` | `story-v3.0.md` |

## 11. 导航栏规范

作品正文中的导航栏使用**相对路径占位符**，在渲染或发布时替换。

**Markdown 源码中**使用以下占位符：

```markdown
{{nav-previous}} | {{nav-toc}} | {{nav-next}}
```

**渲染后**：

```markdown
[上一章](ch-002-xxx.md) | [返回目录](../../README.md) | [下一章](ch-004-xxx.md)
```

禁止在源码中硬编码 `../../../../../../` 等绝对层级路径，因为不同世界观深度不同，硬编码路径会失效。
