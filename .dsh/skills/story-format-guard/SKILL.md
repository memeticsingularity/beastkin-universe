# 故事正文格式骨架（强制）

**唯一权威源**：`docs/spec/11-story-format.md`（**v4.0**）。不要凭记忆、也不要照抄既有文件——
历史遗留有多种写法。骨架可直接复制：
`templates/world-template/work-template/forms/{chaptered,short}/chapters/`。

## 一句话骨架

```
H1 → --- → 导航 → --- → 卷首语 → --- → 正文（0..N 幕）→ --- → 卷尾语 → END → --- → 导航 → --- → 故事评述与感慨
```

## 各块写法

| 块 | 分章 | 短篇 |
|---|---|---|
| H1 | `# Chapter {自然数} {中文标题}` | `# Story {中文标题}` |
| 导航 | `[{上一章}]({路径}) \| [{目录}]({路径}) \| [{下一章}]({路径})` | `[{目录}]({路径})` |
| 卷首语 | `> *{对本章的诗意概括}*` | `> *{故事简介}*` |
| 正文分幕 | `## 第{N}幕 {幕标题}`（英文 `## Act {N} {Title}`） | 同左 |
| 无幕形态 | **合法**：正文连续段落，不写幕标题 | 同左 |
| 卷尾语 | `> *{本章总结/情感升华}*`，在 END **之前** | `> *{故事结束语}*` |
| 结束标记 | `**Chapter {自然数} END**` | `**Story END**` |
| 评述区 | `## 故事评述与感慨` + `> *{导语}*` | 同左 |
| 评述子块 | `### 他们最后的故事` / `### 还活着的人们` / `### 故事感慨` | 同左（可省空子块，至少留 `### 故事感慨`） |

**H1 标题文字**：英文标题用 Title Case（实词首字母大写，`a/the/of/in` 等虚词小写）；
由文件名 slug 派生出来的占位标题同样 Title Case，并登记到 `project-docs/story-format-todo.md` 待作者改写。
校验器只判 H1 的**形态**（`# Chapter {N} {标题}` / `# Story {标题}`），不判大小写。

**硬规则**

1. 结束标记**恰好 1 个**，且必须在卷尾语之后、评述区之前
2. `###` 只用于评述区那三个固定子块；幕标题必须是 `##`，**不得**用 `###`
3. `---` 只出现在固定分界点（导航前后、卷首语前后、正文与卷尾语之间、END 前后）
4. 同一作品内「有幕 / 无幕」保持统一，不要混用
5. 英文作品用 §8 的对应写法（`## Story Commentary and Reflections` 等）

## 空行（预览正确性，最容易翻车）

**会渲染成不同块的两行之间必须有空行**，否则预览里会并成一段或变形：

| 位置 | 必须 | 违反后果 |
|---|---|---|
| 段落之间 | 空一行 | 两段并成一段 |
| `---` | 前后各空一行 | ⚠️ 上一行被当成 setext 标题（整句变大标题） |
| `##` / `###` | 前后各空一行 | 标题不生效或吞掉下一行 |
| `> *{卷首语/卷尾语}*` | 前后各空一行 | 与相邻段落粘连 |
| `【…→…】` 标签行 | 与其下评述空一行；多条记录之间也各空一行 | 标签与评述并成一行 |
| 想分行显示的多行信息 | 改用列表 `- 名称：值`；确需保留**一个连续块**并逐行显示（如 `>` 里的外文名＋中文简介），在行尾留两个空格做硬换行 | 预览里全部并成一段；在 `>` 行之间插空行会**断成两个引用块** |

长篇在源码里硬折行（行尾无句末标点）是允许的——那本就该并成一段，不必补空行。

**引用块（`>`）内要逐行显示**（外文名＋中文简介、卷首语/卷尾语诗行、作品元信息）时，用**行尾两个空格**做硬换行，保持一个连续引用块：

- 该补：上行以句末标点结尾（允许尾随 `*` / `**`）、整行斜体 `> *…*`、下一行是 `**字段**` 标签、短信息行
- **不该补**：同一句话被折行（上行以 `**` 结尾、下行接着写同一句）——补了会把句子劈成两行
- 不适用：引用块内的表格行 `> | … |`
- 校验：`check-format.js` 末尾统计「引用块内未硬换行」（只统计、不阻断；当前为 0）

## 禁止的旧写法（不得回潮）

| 位置 | 禁止 | 应为 |
|---|---|---|
| H1 | `# MS-001: 作品名 - 第N章：标题` | `# Chapter {N} {标题}` |
| H1 | `# 作品名 - 第N章：标题` | `# Chapter {N} {标题}` |
| H1 | `# SS-00N: 标题` | `# Story {标题}` |
| 结束标记 | `**第一章完**` / `**终章**` | `**Chapter {N} END**` |
| 结束标记 | `**完**` | `**Story END**` |
| 结束标记 | 两个标记挤在同一行 | 各占一行 |
| 分幕 | `**Scene-1 {标题}**`（v3.0 旧法） | `## 第1幕 {标题}` |
| 卷尾语 | 写在 END 之后 | 写在 END 之前 |

## 文件命名与位置

- 分章：`<作品目录>/chapters/ch-{三位数字}-<slug>.md`（分卷 `chapters/volume-N/`）
- 短篇：`<作品目录>/chapters/<作品编码>.md`；短篇集 `chapters/<NN>-<slug>.md`
- **正文一律在 `chapters/` 下**（分章与短篇一致，作品根不放正文）
- 形态（Chapter 还是 Story）由**作品内多数文件的既有形态**决定，不要按文件名猜

## 自检

```bash
node scripts/qa/check-format.js <作品目录>
```

- **硬性不合规**必须当场修（H1、结束标记数量/位置、废弃写法）
- **迁移欠债**（无评述区 / 缺子块 / 旧加粗分幕 / 卷尾语位置 / 正文用 `###`）只统计不阻断：
  新写与大修一律按 v4.0，旧正文在其作品下次改版时顺带迁移，清单见
  `project-docs/story-format-todo.md`
- 标题确实无处可取的（无 H1、无文件名 slug、无同章兄弟标题），登记到该 todo，**不要臆造标题**
